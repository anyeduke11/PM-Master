# PM-Master v6.0 需求文档（可开发 · 可验收）

> 版本：v1.0 | 对应 PRD：《02-PRD-v6.0.md》| 论证依据：《01-深度分析与第一性原理评审.md》
> 编号规则：FR=功能需求 / NFR=非功能需求 / AC=验收标准 / P0-P3=优先级
> 阅读方式：每条需求都是"一句话说清做什么 + 怎么算合格"，开发与测试可直接引用编号。

---

## 0. 总则

1. **本文件只包含 v6.0 新增/修订需求**；v5.18.0 与 R2 已交付/已定稿范围不在其内，继续有效。
2. 所有需求遵守项目三大铁律：**规则交代码、判断交 AI、决策交用户**；写操作双确认；失败 fail-loud。
3. 每个阶段交付必须：`node --check` 全过 + 测试基线不降 + `vite build` exit 0 + 诚实标注未实测项。

## 1. R8.1 捕获与坐标（P0）

### FR-16.1 每日一记（P0）
**做什么**：工作台新增"每日一记"入口，30 秒完成三段式结构化日志：今天做了什么 / 遇到什么卡点 / 明天最重要的一件事。
**细节**：
- 一天一条，可补记；同天重复打开是编辑而非新建；
- 落库新表 `daily_notes(id, user_id, date UNIQUE(user_id,date), done_text, blocker_text, tomorrow_text, created_at)`；
- 手记支持一键"转为证据候选"（生成 evidence 草稿，用户确认后入库，不自动入库）；
- 教练会话开场时，若昨天/今天有手记，AI 主动引用（"昨天你记了 X，今天想聊这个吗？"）。
**AC-16.1**：
- [ ] 连续 3 天各记 1 条，第 4 天打开为编辑态且内容保留；
- [ ] 同一天两条手记请求只存在一行（UNIQUE 生效）；
- [ ] "转为证据候选"产生 evidence 草稿（status=draft），确认前不出现在成长记录正式列表；
- [ ] 教练开场引用测试：有手记的会话 system prompt 含该手记内容；
- [ ] 空内容提交返回 400 可读文案（fail-loud）。

### FR-16.2 捕获覆盖率 KPI（P0）
**做什么**：成长看板与设置中心新增"捕获覆盖率"= 近 7 个工作日中有数据流入（每日一记/连接器同步/导入）的天数占比。
**AC-16.2**：
- [ ] 构造 7 天中 4 天有手记 → KPI 显示 57%（4/7，四舍五入到整数百分比）；
- [ ] 零数据日不报错，显示 0% 与空态文案。

### FR-16.3 坐标注册表（P0）
**做什么**：新增标准库 `standard/frameworks.yaml`，结构化定义四个坐标：CSPM（默认）/ PMP / PRINCE2 / IPMA，每个坐标含：等级数、等级名称、维度定义、经验硬指标、证据清单引用。
**AC-16.3**：
- [ ] YAML 加载与既有 `gbt41831.yaml` 校验同等严格（未知字段/缺字段启动即报错）；
- [ ] API `GET /api/v2/standard/frameworks` 返回四坐标元数据；
- [ ] 默认坐标=CSPM 时，现有全部接口行为与 v5.18.0 基线完全一致（回归测试不降）。

### FR-16.4 坐标切换（P0）
**做什么**：设置中心"坐标与框架"区可切换主坐标；切换后等级矩阵、证据清单、成长剧本、雷达视图按新坐标重组；保留原坐标历史快照。
**细节**：
- 切换需二次确认（输入目标坐标名），切换时生成 `coordinate_snapshots` 存档；
- 迁移期内雷达双轨展示（旧坐标灰显 + 新坐标高亮），一个迁移期（一个月度周期）后旧轨隐藏但存档可查；
- 内容层（知识卡/ITTO/模型/训练映射）不随坐标变化，仅"刻度"变化。
**AC-16.4**：
- [ ] CSPM→PMP 切换后：`/api/v2/requirements/:level` 返回 PMP 等级结构；成长记录经验清单换成 PMP 口径；
- [ ] 快照存在：切回 CSPM 后历史评估数据可查；
- [ ] 双确认不符返回 400；
- [ ] 切换不过滤、不删除任何历史证据/会话/分数记录。

### FR-16.5 全表 user_id 预留（P0）
**做什么**：全部业务表幂等迁移增加 `user_id INTEGER NOT NULL DEFAULT 1` 与复合索引；查询层统一带 user_id。
**AC-16.5**：
- [ ] 迁移在既有数据库上重复执行无副作用（幂等）；
- [ ] 本地单用户场景全部既有接口返回值与迁移前一致（数据零损）；
- [ ] 新写入行的 user_id 均为 1。

### FR-16.6 飞书增量同步产品化（P1）
**做什么**：把 v5 已交付的飞书读能力产品化为增量同步：记 `sync_log`（时间/范围/条数/结果），失败降级手动模式并提示。
**AC-16.6**：
- [ ] 连续两次同步，第二次只拉增量（since 参数生效，条数符合预期）；
- [ ] 同步失败（坏 token）时：sync_log 记失败、UI 提示降级、业务流不中断（沿用 v5.7.8）。

## 2. R8.2 判断与排练（P0-P1）

### FR-17.1 决策副驾（P0）
**做什么**：在三个现有位置嵌入决策副驾卡片——① 容差预警卡片；② 周报偏差分析；③ 变更评估。输出固定五段式：建议 / 理由（引用可复算数据）/ 反例 / 可选动作（代价+可逆性）/ 决策权声明。
**细节**：
- 数值计算一律走既有纯代码引擎（EVM/容差/风险矩阵），LLM 只组织语言与二阶推演；
- 副驾给建议后提供"用教练复盘这个决策"一键入口（进入对应 GROW 场景并预填上下文）；
- 副驾建议永不自动执行任何写操作。
**AC-17.1**：
- [ ] 构造 CPI=0.85 超容差项目 → 副驾卡片出现，且"理由"段含真实数值（0.85/基线/容差）；
- [ ] 卡片必含"反例"与"最终决定权在你"两段，缺一段即缺陷；
- [ ] 副驾输出中无任何自动写库动作（审计断言）；
- [ ] 一键教练入口打开教练室且 G/R 上下文预填该偏差数据。

### FR-18.1 干系人模拟器（P1）
**做什么**：新增教练场景类型 `stakeholder_sim`：从干系人地图选一个真实干系人（职位/权力/参与度/历史态度自动注入），AI 扮演其与用户多回合对话；结束后按三维评定（框架清晰度/诉求回应/情绪管理，各 良好/合格/待提升 + 依据引用）。
**细节**：
- 难度三档（配合/中立/刁难）；回合上限 10，用户可随时结束；
- 模拟全程标注"演练中"；模拟记录写入 coach_sessions（scenario=stakeholder_sim），不进该干系人任何真实数据；
- 评定回流人际沟通/谈判/冲突与危机指标（行为分流水，同 v5 钩子机制）。
**AC-18.1**：
- [ ] 选择干系人"CFO·高权力·反对"开始模拟 → AI 首轮即体现反对立场（LLM 输出含质疑/追问）；
- [ ] 结束后产生评定记录，competency_scores 对应指标流水可查；
- [ ] 干系人表数据零变更（审计断言）；
- [ ] 会话中断（关闭页面）后可恢复，恢复后角色一致。

### FR-20.1 跨项目模式识别（P1）
**做什么**：每月 1 日（随 monthly_recalc）产出《个人模式报告》：反复失误 / 系统性偏差 / 优势惯性 / 规避行为四类，结论必须附样本条目引用；报告可生成训练任务。
**细节**：
- 规则引擎先做候选筛选（如"范围变更后 30 天内超期"出现 ≥3 次），LLM 只做归因表述，不发明样本；
- 用户可对每条模式标记"不认同"（不再推荐同类任务）或"忽略"；
- 报告存档可回溯。
**AC-20.1**：
- [ ] 构造 3 个项目"范围变更→超期"数据 → 报告出现"反复失误"类条目且引用 3 个项目 id；
- [ ] 样本不足（<3）不产出该类结论；
- [ ] "不认同"后下月报告不再出现该模式；
- [ ] 一键生成训练任务写入 training_tasks，来源标 `pattern_mining`。

## 3. R8.3 结果与闭环（P1）

### FR-21.1 360° 反馈入口（P1）
**做什么**：生成匿名反馈问卷（上级/同事/下属三套，各 3-5 题，行为锚定表述对标 29 指标）；回收 ≥3 份才出聚合报告；作为素质维第四信号层。
**细节**：
- 初始权重：自评 15% / 情景 35% / 行为 35% / 360 反馈 15%（信号层总权重归一，原三层按比例拆分）；
- 360 只校准、不自动改分；聚合报告 ≥3 份才生成，单人反馈永不可见；
- 问卷链接本地生成，不经过任何外部服务。
**AC-21.1**：
- [ ] 三套问卷生成且题目含行为锚定（不是"你上级强吗"而是"他在预算超支时是否主动升级"类表述）；
- [ ] 2 份回收 → 不生成报告并明示"还需 1 份"；3 份 → 生成聚合报告；
- [ ] 报告不包含任何可定位到个人的信息；
- [ ] 360 数据进入月度重算流水且可回滚。

### FR-21.2 认证考试结果回填（P1）
**做什么**：成长记录新增"外部认证"类型：可录入考试/认证结果（通过/未过/日期）。通过则知识维信度提升；未过触发弱区重测任务。
**AC-21.2**：
- [ ] 录入"CSPM-4 通过" → 该记录进入 evidence 且知识维 confidence 标注提升；
- [ ] 录入"未通过" → 自动生成弱区补测训练任务（drill.tasks）。

### FR-21.3 项目成败标记（P1）
**做什么**：项目结项时标记 成功/部分成功/失败 + 主因（下拉：范围/进度/成本/质量/干系人/外部）；进入模式识别数据源。
**AC-21.3**：
- [ ] 标记后项目档案终态含该字段；模式报告可引用。

### FR-15.x 反博弈三件套（P1）
**做什么**：
- **盲评**：E 阶段指标评定由独立会话执行，system prompt 不含用户当前等级与历史评定；
- **对抗性校准题**：每期评估混入 2-3 道反直觉题（测迎合倾向：如故意设置"看起来该选 A 其实选 B"的题），得分单列不计入知识维，只计入"迎合指数"观测；
- **随机抽验**：月度重算对 10% AI 评定做二次复评（不同 prompt/温度），分歧 >1 档标记人工复核队列。
**AC**：
- [ ] 盲评会话 system prompt grep 不到等级字段；
- [ ] 校准题不计入知识维分数（构造验证：答对答错知识维分不变，迎合指数变）；
- [ ] 抽验触发日志可查，分歧条目进复核队列。

### FR-23.1 闭环率 KPI（P1）
**做什么**：成长看板新增"闭环率"=（差距→训练→证据→分数提升 的完整链条数）/ 总训练任务数（承接 R2 W3.1 growth_links 设计）。
**AC**：
- [ ] 构造 10 个任务其中 4 条完整闭环 → 显示 40%；
- [ ] 断链任务可下钻看到断在哪一环。

## 4. R8.4 通用化（P2-P3）

### FR-16.7 连接器扩容（P2）
**做什么**：按 Adapter 框架新增 Jira / 邮件（IMAP）/ 会议转写（音频或文字稿）三个连接器；每个连接器实现 pull→normalize→diff→commit 同接口。
**AC**：
- [ ] 每个连接器有：注册、启停、健康探测、sync_log 四件套；
- [ ] Jira 拉取的 issue 归一化为统一事件模型并可关联项目；
- [ ] 会议转写稿可抽取行动项并进纪要（复用 v5 纪要行动项管线）。

### FR-19.1 行业模板包机制（P2）
**做什么**：把 W4 验证过的垂直模板抽象为"行业插件"机制：一个行业包 = 场景模板 + 字段 schema + 计算规则 + 报告结构，注册后即可用。首批示范：把 W4 重构为"风险评估行业包"。
**AC**：
- [ ] 行业包可注册/启停/卸载，卸载不影响其他数据；
- [ ] W4 重构后功能与现状等价（回归测试）。

### FR-22.1 敏感数据治理（P3）
**做什么**：风险资产表增加数据分级（公开/内部/敏感）字段；分级为"敏感"的数据默认不进入外部 LLM 调用（本地降级提示）；导出支持脱敏选项。
**AC-22.1**：
- [ ] 标"敏感"的资产行参与 LLM 抽取时被剔除并有可见提示；
- [ ] 脱敏导出的文件中敏感字段被掩码。

### FR-22.2 审计日志（P3）
**做什么**：数据导出/删除/坐标切换/360 报告生成记审计日志（谁/何时/做了什么/范围），设置中心可查。
**AC-22.2**：
- [ ] 执行一次全库导出 → 审计日志新增一条且字段完整。

### NFR-Mobile 移动端评估（P3）
**做什么**：PWA 可行性评估（manifest + 离线外壳 + 每日一记移动优化），出评估结论再决定是否立项，不默认做。

## 5. 非功能需求（NFR）

| # | 需求 | 口径 |
|---|---|---|
| NFR-1 | 性能 | 决策副骑卡片生成 ≤8s（快模型）；每日一记提交 ≤500ms；模式报告生成可异步（通知到达即可） |
| NFR-2 | 确定性优先 | 一切数值（EVM/容差/矩阵/KPI/覆盖率/闭环率）必须纯代码可复算，禁止 LLM 计算 |
| NFR-3 | 隐私 | 用户数据不出本机除非用户显式配置外部 LLM；"敏感"分级数据强制本地降级 |
| NFR-4 | 可观测 | 新增能力全部落 llm_calls（purpose 登记，防漂移测试覆盖）；捕获/同步/模拟/副骑各有 sync_log 或会话记录 |
| NFR-5 | 降级 | 无 LLM key 时：一记/KPI/坐标切换/快照全可用；副骑/模拟/模式报告走降级模板并标注"降级" |
| NFR-6 | 无障碍 | 新组件沿用令牌体系与 AA 对比度；键盘可达；toast aria-live |
| NFR-7 | 回归 | 每阶段测试基线不降；每阶段补对应单测/边界/e2e（参照 v5 J/K/F 编号传统） |

## 7. 明确不做（Out of Scope，防止范围蔓延）

1. 不做多租户权限体系与云端部署（组织模式仅数据模型预留）；
2. 不做考试模拟（D5 不变）；
3. 副骑不自动执行写操作（D14/N1 不变）；
4. 360 反馈不做实名渠道，只做匿名聚合；
5. 不做原生 App，只做 PWA 评估；
6. 不承诺"开箱即用的任意用户体验"——通用模式仍需一次坐标选择与数据源配置（D11）。
