## 1. 产品概述

### 1.1 定位（v6.0 修正）

**PM-Master 是一个 AI Native 的项目经理大师助手**：它同时做两件事——

1. **替 PM 看清工作**：把散落在各处的项目数据聚起来，算清楚（EVM/容差/风险），在该说话的时候说话（预警、例外、聚合建议）；
2. **陪 PM 长成本事**：把每一次真实工作变成能力证据，对标成长坐标，给出下一个训练任务。

一句话：**感知靠捕获，判断给建议，协调给排练，成长有证据。**

### 1.2 三种用法（同一内核，v6.0 新增）

| 用法 | 用户 | 坐标 | 数据 | 状态 |
|---|---|---|---|---|
| **A. 个人成长模式** | 已入驻的一号用户 | CSPM（默认） | 飞书 + 手动 | 已交付，持续用 |
| **B. 职业通用模式** | 任意 PM 从业者 | 坐标可切换（CSPM/PMP/PRINCE2/IPMA） | 连接器 + 每日一记 | **v6.0 主线** |
| **C. 组织模式** | 团队/PMO | 组织坐标 + 多用户 | 多用户数据模型 | 数据模型预留，功能后置 |

设计铁律不变：**代码零等级硬编码**；一切等级/坐标相关内容读标准库 YAML，随档案自适应。

### 1.3 目标用户与等级模型

- 等级无关（level-agnostic）系统：任意用户冷启动评估后，从其真实定位（L1-L5 任意等级，项目/PMO 双通道）开始成长——**沿用 v5.18.0 §6.5 不变**。
- v6.0 新增：**坐标无关（framework-agnostic）**——成长坐标从"CSPM 骨架"变为"可切换坐标 + 四体系可装配"（见第 16 章）。

### 1.4 核心价值主张

| 用户诉求 | 系统回应（v6.0 扩充） |
|---|---|
| 有理论 | 知识陪练：17 领域 × 3 层认知深度 × 可切换坐标 |
| 有知识 | 思维教练（45+ 核心模型）+ 个人知识资产库 |
| 有经验 | 成长记录：实战自动沉淀 → 对标评审要求的经验清单 → **外部校准（360/考试回填）** |
| 有技术 | 项目工作台：WBS/风险册/EVM/干系人/汇报实操工具 |
| **（新）信息散** | **捕获层：连接器 + 每日一记，让 AI 看得见你的工作** |
| **（新）决策难** | **决策副驾：基于全部历史数据给出"建议+理由+风险"** |
| **（新）协调难** | **干系人模拟器：和"难缠的 sponsor"排练到会为止** |

### 1.5 成长飞轮 v2（v6.0 核心修正）

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
   捕获层(连接器/一记) → 实战工作 → 沉淀证据 → 评估雷达 → 差距分析 → 训练任务
        ↑                                    ↑                          │
        │                                    │                          │
   外部校准(360/考试/项目成败) ──── 校准 ─────┘                    完成训练
        │                                                              │
        └── 结果口径：度量"结果"而非仅"活动" ◀─────────────────────────┘
```

v5 飞轮只度量活动（训练次数、证据条数）。v6 飞轮新增**结果反馈环**：雷达分数必须接受真实世界检验，否则是空转。

### §6 评估引擎修订（v6.0）

- **信号层不变**：自评 20% + 情景 40% + 行为 40%。
- **行为证据口径扩展**：从"产物存在"扩展到"成果质量"——产物被采纳/被证实/被外部引用可加权（如：周报定稿后获上级采纳、识别的风险实际发生、谈判达成目标）。
- **新增信度标注**：每期雷达输出附 `confidence`（样本量、证据新鲜度、评定一致性的合成），证据不足的指标标注"证据不足"（沿用 v5 防卡点设计）。
- **新增反博弈三件套**（D15）：
  - 盲评：E 阶段评定由不知道用户当前等级/历史评定的独立会话执行；
  - 对抗性校准题：每期混入 2-3 道"反直觉题"（专测迎合倾向）；
  - 随机抽验：月度重算时对 10% 的 AI 评定做二次复评，分歧 >1 档的标记人工复核。

## 16. 捕获层与连接器框架（v6.0 新增 · P0）

> 第一性原理依据：第①单元"知道现在发生了什么"是其他一切的地基。v5 的系统在此几乎空白（手动粘贴），这是最大结构性缺口。

### 16.1 架构：连接器框架（Adapter 模式）

```
统一数据模型（events / artifacts / notes）
        ▲
  Connector Registry（注册/启停/健康/同步日志）
        ▲
 ┌──────┼──────┬──────┬──────┐
 Feishu  Jira  Excel  邮件   ── 每个连接器实现同一接口：
 (已有)  (新)  导入(已有) (新)   pull(since) → normalize → diff → commit
```

- 每个连接器只做三件事：拉取、归一化到统一模型、增量提交；冲突/失败记 sync_log，降级不阻塞（沿用 v5.7.8 兜底原则）。
- 优先级：飞书增量同步（已有读能力产品化）→ Excel/CSV（已有导入产品化）→ Jira/Asana → 邮件（IMAP）→ 会议转写（音频/文字）。

### 16.2 每日一记（最小捕获，先行交付）

30 秒完成的结构化日志：今天做了什么 / 遇到什么卡点 / 明天最重要的一件事。落库为 `daily_notes`，是：

- 教练会话的预热上下文（"昨天你记了资源被抢，今天聊聊？"）；
- 证据的草稿源（月末一键把高价值笔记转 evidence 候选）；
- 跨项目模式识别的数据源（见 §20）。

### 16.3 验收口径

捕获覆盖率 = 本周有数据流入的天数 / 工作日天数，进设置中心 KPI。目标：个人成长模式 ≥60%，才谈得上"实战即训练"。

## 17. 决策副驾（v6.0 新增 · P0）

> 第一性原理依据：第②单元。v5 的助手面只会"执行"，不会"判断"。大师助手的"大师"必须体现在判断力上。

### 17.1 能力定义

当系统检测到决策点时（容差超限、风险升级、变更评估、阶段门控），决策副驾输出：

```
【建议】继续推进 / 转向 / 升级（三选一或组合）
【理由】引用你的历史数据（"类似偏差在上个项目 3 周后恶化"）
【反例】什么情况下这个建议是错的（二阶思维强制项）
【可选动作】每个动作的代价与可逆性
【决策权】最终决定永远是你的（确认后才执行任何写操作）
```

### 17.2 与既有模块的关系

- 不是新页面：嵌入预警卡片、周报偏差分析、变更评估三处现有位置；
- 与教练面分工：**副驾给判断，教练练判断**——副驾每次给建议后，可一键"用教练模式复盘这个决策"；
- 实现约束：建议必须引用可复算的数据（EVM/容差/风险册数值），LLM 只负责组织语言与二阶推演，不负责算数（规则交代码，判断交 AI，决策交用户）。

## 18. 干系人模拟器（v6.0 新增 · P1）

> 第一性原理依据：第③单元"让别人愿意做"。v5 只有静态登记册，没有互动排练。

- 基于干系人地图中的真实干系人（职位、权力、参与度、历史态度），AI 扮演该干系人与用户对话：向上汇报排练（刁难的上司）、跨部门谈判（不配合的平级）、团队冲突（消极的骨干）。
- 难度分级、回合制、结束后按"框架清晰度/诉求回应/情绪管理"评定并回流人际沟通/谈判指标。
- 安全边界：模拟内容标注"演练"，不写入真实干系人任何数据；模拟记录入 coach_sessions 新场景类型 `stakeholder_sim`。

## 19. 组织上下文档案 Org Profile（v6.0 新增 · P2）

> 第一性原理依据：L4/L5 能力（治理、战略、组合）长在组织里，真空中练不出来。

轻量组织档案（用户手动维护，AI 辅助抽取）：

- 治理结构：汇报线、项目委员会、PMO 职责、决策权限（谁能批什么）；
- 项目组合：在跑项目清单与优先级（本地优先，预留飞书多表直连——R2 Q3 决策不变）；
- 节奏：经营分析会、评审会、考核周期。

用途：① 汇报/教练场景自动带组织语境（"你的 sponsor 是 CFO，他关心现金流"）；② 治理类指标（战略/治理结构与流程）的训练素材生成；③ 组织模式（用法 C）的数据基础。

## 20. 跨项目模式识别 Pattern Mining（v6.0 新增 · P1）

> 第一性原理依据：个体行为模式是最有价值的个人化知识，v5 完全未开采。

每月由规则 + LLM 协同扫描全部项目/会话/证据，产出《个人模式报告》：

| 模式类型 | 示例 | 产出 |
|---|---|---|
| 反复失误 | "4 个项目均在范围蔓延后超期" | 针对性训练任务 + 教练场景推荐 |
| 系统性偏差 | "估算系统性乐观约 20%" | 估算校准任务（PERT/参考类比对） |
| 优势惯性 | "风险识别质量高于平均" | 知识贡献候选（M3 卡片） |
| 规避行为 | "冲突场景会话完成率最低" | 轻量切入任务 |

约束：模式结论必须附样本证据（引用了哪些条目），可解释、可申诉（用户可标记"不认同"）。

## 21. 结果校准与外部反馈（v6.0 新增 · P1）

> 第一性原理依据：没有结果反馈的飞轮在空转。

- **360° 反馈入口**：生成匿名反馈问卷链接（上级/同事/下属各 3-5 题，对标 29 指标行为锚定），回收后作为素质维第四信号层（初始权重 10%，从行为证据中拆分，信号层总权重重归一）。
- **认证/考试结果回填**：CSPM/PMP 等考试结果可录入，作为知识维的外部校准点（通过 = 知识维信度提升；未过 = 触发弱区重测）。
- **项目成败标记**：项目结项时标记"成功/部分/失败"及主因，进入模式识别与雷达校准。
- 所有外部数据只用于校准，不自动改分（改分必须经月度重算流水，可回滚）。

## 22. 多用户与安全治理（v6.0 新增）

### 22.1 多用户数据模型预留（D16）

- 全部业务表加 `user_id INTEGER NOT NULL DEFAULT 1` + 复合索引；查询层统一带 user_id 过滤（本地单用户无感知）。
- 会话/记忆/画像天然按 user 隔离（v5.17.4 域门控机制已具备雏形）。
- 组织模式（用法 C）功能：共享项目空间、上级视角、团队雷达——**仅做数据模型与接口预留，不在 v6.0 实现**。

### 22.2 安全与合规治理（P3）

- W4 敏感数据：风险资产表增加数据分级字段与脱敏导出选项；
- 审计日志：数据访问/导出/删除全审计（当前可观测性仅 llm_calls）；
- LLM 外发边界：明确哪些字段可出本机（默认：分级为"敏感"的数据不进任何外部 LLM 调用，本地 mock/降级提示）。
